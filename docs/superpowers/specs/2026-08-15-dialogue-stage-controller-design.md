# 陪伴式对话阶段控制器设计

## 目标

让 `companion` 模式从“用户输入后立即给出长篇解释和方法”转为循序的陪伴式对话：先倾听和探索，再澄清，最后才在合适时机反馈或给出一个小行动。

## 范围与边界

- 仅改变 Node `agent-service` 中 `companion` 的普通对话提示词；`popsci` 不受影响。
- 不新增数据库表或浏览器接口。阶段由本轮输入和已重建的会话历史即时推导。
- 高/紧急风险仍由既有确定性规则和固定危机回复处理，绕过普通 Agent。
- 保留现有工具、状态回顾、摘要检查点和用户隔离。

## 阶段推导

只计用户消息，不计助手文本：

| 条件 | 阶段 | 本轮目标 |
|---|---|---|
| 当前输入明确索要方法、建议或“怎么办” | `micro_action` | 共情后给一个小而可执行的建议，再用一个问题确认是否适合 |
| 本轮计入后，用户消息少于 3 条 | `explore` | 反映感受并问一个开放问题；不解释、不列方法 |
| 用户消息为 3–5 条 | `clarify` | 基于已知内容问一个具体澄清问题；不列方法 |
| 用户消息超过 5 条 | `reflect` | 简短总结已出现的模式；仅在用户要求时解释，仍以一个问题继续探索 |

每一阶段都要求简短、自然、非诊断；除 `micro_action` 外不主动给建议。回复不使用多项列表，最多两段，并以至多一个自然问题收束。

## 架构

新增纯函数模块 `agent-service/src/dialogue.ts`：

- `deriveCompanionDialoguePolicy(messages, input)` 返回阶段、用户轮次和是否允许建议/解释。
- `buildAgentSystemPrompt(mode, policy?)` 将基础安全边界与当前轮的阶段约束组合为 Pi `Agent` 的动态系统提示词。

`service.ts` 在构造 Pi `Agent` 前计算策略，并将动态提示词传入 `initialState.systemPrompt`。Provider 仍只在模型组合层解析；Agent Core 不接触 DeepSeek 配置。

## 验收

1. 首轮表达困扰得到共情和开放式探索，而非主动方法清单。
2. 第 3–5 个用户回合得到基于已说内容的单一澄清任务。
3. 明确问“怎么办”时允许一个微小建议，但仍保持一问一答。
4. 助手消息不推进阶段；科普和危机路径不受影响。
5. 纯函数与完整 Node 测试通过，运行中的 Flask 与 Agent 健康检查可用。
